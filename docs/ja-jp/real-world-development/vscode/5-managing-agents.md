GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を受け入れるか元に戻し、追加のプロンプトで会話を方向付けて作業を調整または拡張できます。エディターを離れる必要はありません。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして受け入れる。
- セッションの途中でエージェントに指示し、高コントラストモードに加えてライトモードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティのカスタムエージェントは、高コントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加したいとのことです。新しい会話を始める代わりに、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する手順が表示されます。調査したファイル、実行したコマンド、提案する編集内容を確認できます。ファイル編集はそれぞれ差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取り、ファイルの編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** 表示を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントが高コントラストモードを実装するまで待ちます。完了すると、変更内容の概要が表示されます。

## エージェントにライトモードを追加するよう指示する

高コントラストモードの実装後、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは前の作業で変更したコンポーネント、スタイルの方針、設定したローカルストレージのパターンなど、すべてのコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは以前の変更を確認し、ライトモード用の追加を提案します。
3. 高コントラストモードの場合と同様に、変更ごとに差分をレビューします。各差分で **Keep** または **Undo** を選びます。
4. エージェントの方針が希望と異なる場合 (たとえば切り替え UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 実行中のセッションに指示を出す方が、最初からやり直すよりも迅速です。追加のプロンプトで変更を依頼できます (例: 「CSS を簡略化し、セレクターの重複ではなく CSS 変数を使う」)。
>
> 方針を修正できます (例: 「3 つ目の切り替えを追加せず、ライトモードを既存の設定パネルに統合する」)。
>
> 作業範囲を拡張することもできます (例: 「両方の切り替えにキーボードショートカットも追加する」)。

## 作業セットをレビューする

コミットする前に、エージェントが変更したすべての内容を簡単に確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開いて差分を確認します。カスタムエージェントのアクセシビリティパターンとして、ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保存が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで進行中のセッションを監視して方向付けました。各ファイルの編集を確認し、変更を受け入れるか元に戻し、コンテキストを維持したまま追加のプロンプトを送信して作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を受け入れるか元に戻す。
- 追加のプロンプトを使って、実行中のセッションに指示を出す。

次の[レッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
